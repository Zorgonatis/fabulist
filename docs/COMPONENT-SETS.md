# Component Sets — the Technology set and the reusable core

**Status:** freeze record + inventory, 2026-10-23. This names the component set the generator
emits today and classifies every component in it. The classification is what a future profile set
starts from: copy the reusable core, replace the flavoured group, do not invent a second
structural vocabulary.

**Sources of truth:** `prompts/generated/library.spec.json` (the spec the engine gate reads),
`prompts/generated/library.doc.txt` (the doc the narrator is taught), `prompts/generated/set.json`
(the set manifest). All three are generated by `frontend/scripts/generate-library-spec.mjs` from
`frontend/src/lib/openui/schemas/flavors.ts` plus the generator's inline `INFRASTRUCTURE` block.
The renderer/file contract is `docs/COMPONENT-PATTERNS.md`; the surface design is
`docs/UI-LANGUAGE.md`. The ruling that the vocabulary is one generated spec is ADR-018; the
freeze itself is ADR-024.

**Versioning is `major.minor.patch`, and this set starts at `1.0.0`.** A breaking change to the
surface the model learned — a renamed component, an added or reordered positional prop, a
retargeted hint — is a **major** bump (`2.0.0`). Additive, backward-compatible vocabulary is
**minor** (`1.1.0`); anything that changes no call shape (renderer styling, tokens, markup,
non-taught copy) is **patch** (`1.0.1`). The version is authored in the generator's `SETS` entry
and emitted into `set.json` and `prompts/sets/index.json`; `spec_version` remains the
content-hash fingerprint that answers a different question ("are these the bytes the engine
gated?"). There is no `1` / `tech/1`-style slug anywhere: an older freeze record's `tech/1` means
`technology/1.0.0`.

**What the freeze pins.** Component names, positional prop order, prop types, and the taught doc.
Those are the set's public surface: the call shape the model learned and the table the engine
gate validates. Renderer styling may change inside a version (tokens, motion, markup), but
renaming a component, adding or reordering a positional prop, or retargeting a hint is what makes
the next major version `2.0.0`.

**What it does not pin.** The render implementation, the fixture set, and the preset copy that
sits around the library (the directive stack and the prompt flows). Those move without a set
version as long as every taught call still parses and renders.

**The identity is the artifact's, not this record's.** `id`, display name and version live in the
set's own manifest (`prompts/generated/set.json`: `id: "technology"`, `name: "Technology"`,
`version: "1.0.0"`) and in the registry entry (`prompts/sets/index.json`, which also names
`default_set: "technology"`), emitted by `frontend/scripts/generate-library-spec.mjs` and pinned by
`tests/test_library_spec.py::test_set_manifest_describes_the_spec`. Only the DIRECTORY keeps the
historical `prompts/generated/` name — the directory is a path, not the identity.

### The vocabulary, as taught

The positional signatures below reproduce `library.spec.json`'s taught surface (deep nested
message/stat keys abridged); they are the DSL contract, not a proposal. `options` is always the
single trailing object; it is accepted even where a component renders nothing from it.

```
ScenePane(title: string, children: component[], options?: object)
MeterBar(label: string, value: number, max: number, options?: object)
ObjectCard(name: string, kind: string, description: string, options?: object)
BeatCard(text: string, options?: object)
Mindscape(title: string, debris: {text, weight, kind}[], texture: string, image: string, mood: string, options?)
Interface(mode: string, title: string, lines: string[], options?)
Document(docType: string, title: string, body: string, signature?: string, options?)
Artifact(name: string, kind: string, rarity: string, flavor: string, stats: string[], options?)
DialogueSpotlight(speaker: string, line: string, tell: string, options?)
ReactionSpotlight(face: string, thought: string, options?)
FailureAchievement(icon: string, title: string, description: string, footer: string, options?)
Memory(era: string, fragments: string[], edge: string, options?)
Entrance(name: string, role: string, signature: string, options? {glyph?, art?, markers?})
Clash(attacker: string, defender: string, intensity: number, note: string, options?)
Custom(title: string, html: string, css?: string, options?)
Phone(thread: string, messages: {from, text, time, status, reactions?, day?}[], options? {glyph?, art?, me?, typing?, clock?, battery?})
SMS(mode: string, title: string, messages: {from, text, time, status, reactions?, day?}[], options? {glyph?, art?, me?})
Monitor(mode: string, title: string, lines: string[], options? {glyph?, art?, theme?})
PostIt(notes: {text}[], options?)
SocialPost(author: string, handle: string, body: string, stats: {likes, reposts, comments}, reply?: {author, handle, text}, options?)
```

The generator groups these for the doc as **Custom** (first-listed for salience), **Infrastructure**
(the four fallbacks), **Scene flavors (10)** and **Artifact reproductions (5)**. The grouping is a
prompt-salience decision in the generator, not a property of the spec.

## 2. How to read the classification

- **HARD REUSABLE** — the component's shape encodes no fact about the world's technology, period
  or genre. Its props are text, numbers and free labels; its composition is a way of looking at a
  scene, not a claim about what exists in it. A future profile set copies the schema and the
  renderer unchanged; only the surrounding copy changes. The test: imagine the scene in a
  stone-age camp or a star-faring court — if the component is the same component with different
  words, it is core.
- **DELIBERATELY TECHNOLOGY-FLAVOURED** — the component reproduces a specific piece of present-day
  furniture (electronics, print-era media, office supplies), or its composition only makes sense
  where that object exists. A future profile set replaces it; it does not re-derive it from
  scratch. This is the whole point of the split: the Technology set says exactly what the next author
  must swap, so they spend their effort on the replacement instead of rediscovering the container,
  the glyph slot or the options object.

Two kinds of flavour are **not** technology-flavour and must not send a future author forking a core
component:

- **The game register.** `Artifact`'s rarity ramp and stat rows and `FailureAchievement`'s
  trophy are game-UI idioms, not a period. They read the same in a fantasy set, a sci-fi set and
  a modern one.
- **The glyph vocabulary.** Emoji/kaomoji in `glyph`, ASCII in `art`, and the serif/display type
  in `DialogueSpotlight` and `Entrance` are house-wide devices (`docs/UI-LANGUAGE.md` §2–3).
  Every set wants them; they are not evidence that a component belongs to this era.

## 3. Hard reusable core — 14 components

| Component | Group | Why it is reusable |
|---|---|---|
| `ScenePane` | Infrastructure | The root placard plus an ordered child list — a container whose only content is free text. It knows nothing about the world. |
| `MeterBar` | Infrastructure | A labelled `0..max` gauge. What is being measured is the set's copy; the shape is a bar. |
| `ObjectCard` | Infrastructure | A name/kind/description pocket tag. Its curated default glyphs (`relic`, `weapon`, `curio`, `quest`, `trinket`) are fallbacks and the model's `glyph` overrides them. |
| `BeatCard` | Infrastructure | One italic narration paragraph — the plainest possible surface, and the fallback when no object exists. |
| `Mindscape` | Scene flavor | Contradictory thought fragments weighted against each other; inner life is not era-bound — a mindscape surface is theme-agnostic, not tied to an age. `Biological NPCs only` is preset copy, not a schema constraint. |
| `Document` | Scene flavor | A letterhead/body/sign-off paper artifact; every period has documents, and `docType` picks the dress. No era literal in the component — tone tokens only. |
| `Artifact` | Scene flavor | An object-examination card (rarity + stat rows). That is a game register, not a setting; any profile that gamifies objects reuses it. |
| `DialogueSpotlight` | Scene flavor | Speaker, the line, and the delivery tell — a pull-quote. A signature line is not period furniture. |
| `ReactionSpotlight` | Scene flavor | One enlarged face plus one internal thought; the face is a glyph slot, not a technology. |
| `FailureAchievement` | Scene flavor | A trophy card for a comedic failure. "Achievement Unlocked" is a game-UI register, not a date; only the sarcastic footer is tone-specific. |
| `Memory` | Scene flavor | An era caption, two to four shards and a dissolving edge — the shape of recall, not a medium. The polaroid-style frame is styling; a pre-photography set can keep the shard composition and restyle it. |
| `Entrance` | Scene flavor | A first-appearance title card. Every setting introduces a character, and the defining visual is supplied as text plus `markers`. |
| `Clash` | Scene flavor | A two-sided impact frame driven by a `0..100` intensity. Every setting has physical force. |
| `Custom` | Escape hatch | A shadow-DOM raw-markup surface. By construction it carries no world model — and it is where a new profile's one-off artifacts go while their typed replacements are being built. |

## 4. Deliberately technology-flavoured — 6 components

| Component | Group | What makes it technology-flavoured | Replace with |
|---|---|---|---|
| `Interface` | Scene flavor | Its modes are `terminal`/`hologram` machine chrome and its voice is the machine's. It exists to render a screen, a readout or a device badge. | The profile's own readout surface (a scrying pane, a ship's log slate, a notice board of pinned slips) — or drop it, if the profile has no machines. `Custom` can cover the gap meanwhile. |
| `Phone` | Artifact reproduction | A smartphone's full chrome: status bar with the narrative clock, contact header, encryption notice, read ticks, reaction pills, day separators. | The period's group-communication artifact (a letter chain, a radio net, a whispering gallery) — or drop it. |
| `SMS` | Artifact reproduction | The push-notification lock-screen banner and the carrier text thread; the banner is an OS affordance, not a diegetic object. | Its parent medium's short-message equivalent, or drop it with `Phone`. |
| `Monitor` | Artifact reproduction | A computer desktop, a system error dialog, a BSOD and CRT phosphor — the machine's own screen. | Whatever screen the profile's machines own; `Custom` is the honest bridge. |
| `SocialPost` | Artifact reproduction | A social-feed card: handle, avatar, likes/reposts/comments, the first reply only. | The profile's public-notice medium (a broadsheet column, a town-crier's sheet, a bulletin board, a pirate-radio transcript). |
| `PostIt` | Artifact reproduction | Era-bound office supply rather than electronics: an adhesive note with a curled corner and the sticky-pastel literal family. It is in this group because it is contemporary furniture. | The period's note surface (wax tablet, pinned parchment, chalk slate, corkboard memo). Keep the composition — one to three short texts, tilted and overlapping — and change the material. |

Why `PostIt` sits here and not in the core: the test is "not bound to a specific genre **or
era**". A post-it is a 1980s office object; a fantasy or historical profile cannot use it
unchanged. `Memory`'s polaroid frame is the same kind of styling, but the frame is decorative
around a genre-neutral shard composition, so it stays core with a note.

## 5. Starting a new profile set

A *profile set* is the component vocabulary a different experience profile teaches. It is not yet
a field of the D33 experience-profile envelope (which carries world, cast, books, preset and
assistants); today a set is a directory swapped through the component-library store.

1. **Copy the core.** Take the 14 hard-reusable components' `.svelte` files and their schemas
   unchanged, keeping names and positional order. Do not re-derive `ScenePane`'s child union, the
   trailing `options` object, the glyph/art slots or the degradation rules — they are already
   paid for.
2. **Decide the flavoured group.** A contemporary-adjacent profile keeps all six. A period
   profile replaces `Phone`, `SMS`, `Monitor`, `Interface`, `SocialPost` and `PostIt` with its own
   equivalents; it may keep any of them deliberately as an anachronism, but that is a profile
   decision, not a default.
3. **Author the replacements** against `docs/COMPONENT-PATTERNS.md` — front-loaded design, typed
   container, tokens only, total degradation, `data-openui` anchors, a fixture per component.
4. **Retarget the set-specific copy** — the components are only half the set:
   - `flavorMeta` in `schemas/flavors.ts` (`bestFor`, `docHint`, `rules`) becomes the taught
     doc's per-component lines;
   - the generator's `COMPONENT_USAGE`, `FLAVOR_NUDGE` and `RETIRED_ROUTING` are the trigger
     table and the retired-name routing;
   - the craft sections' worked example (`Interface` + `Mindscape`) is technology-flavoured; write the
     profile's own exemplar.
5. **Regenerate, never hand-sync.** `cd frontend && node scripts/generate-library-spec.mjs`,
   then `--check` for byte-idempotence. The artifacts are the set; there is no Python component
   list to edit (ADR-018).
6. **Verify.** `uv run pytest -q` (it pins the spec shape, the manifest, the doc and the
   registry/spec parity) and `cd frontend && npm run check`.
7. **Swap it in.** A set directory holds `set.json` + `library.spec.json` + `library.doc.txt`; the
   store resolves `FABULIST_LIBRARY_ARTIFACT_DIR`/`FABULIST_DSL_SPEC` → the session's selected set
   (a `set_swapped` log row) → `prompts/generated/`, and the selection takes effect at the next
   turn boundary (`src/fabulist/dsl/sets.py` + `store.py`). The manifest's `components` must be a
   subset of the set's own spec, and the **client** must already render every name: component
   names are compiled into the frontend registry, not read from the set.

Consequence of step 7, and the practical reason the core matters: a set that uses only the 14
hard-reusable names is **pure data** — it renders through the existing frontend build with no
frontend work. Every replacement component needs the frontend lane (component + schema + registry
entry + regeneration). Until those land, `Custom` is the data-only route for a new profile's
one-off artifacts.

## 6. Set data at runtime

- The store is hot-reloadable: regenerating or swapping a set takes effect on the next turn with
  no engine restart (`library.spec.json`, `library.doc.txt`, `set.json` are data, not code).
- A missing artifact is the documented fallback (flavors.json + the four infrastructure
  components); a present-but-corrupt artifact keeps the last good snapshot and reports why.
- Selection is **per-session** (ADR-026): `POST /api/sessions/{sid}/component-set {"set_id"}`
  appends one `set_swapped` log row and takes effect at the NEXT turn's narrator build
  (`resolve_component_set` → `sets.session_snapshot`). `GET /api/component-sets?session_id=` is
  the picker's catalog (id/name/version/kind/loadable). One session's swap never retargets
  another: the store caches content per set directory and binds a directory per session.
- The door refuses a set the client cannot render (422 with the offending names, ADR-025) and a
  set whose artifacts do not read (422 with the reason) — a swap never strands the next turn.
- The swap is announced once, through the log row's frozen notice in the prompt tail — never a
  rewrite of the stable prefix (ADR-005). The cache cost of a swap (one full re-prefill after the
  library block) is ADR-025's, stated there and measured by the selection probe.
- The taught doc, the engine gate and the strip helper all derive from the same spec, and the
  render registry is generated from the same schemas, so a taught component can never be
  unrenderable, or the reverse (ADR-018).

## 7. Audit notes — inconsistencies found, left unfixed

The audit compared every component's schema and renderer against `library.ts` and the generated
spec. Names, positional order and prop types are in lockstep across `flavors.ts` → `flavors.json`
→ `library.spec.json`, and the generator's `INFRASTRUCTURE` block matches `library.ts`. The
following do **not** contradict the spec's shape but will mislead the next reader; they are
reported here, not fixed (this lane freezes, it does not regenerate):

1. **The manifest's set identity is generated, not hand-tuned** — `prompts/generated/set.json`
   carries `id: "technology"`, `name: "Technology"`, `version: "1.0.0"`; editing it by hand fails
   the generator's `--check`. (Resolved by the rename regeneration; kept here so the next reader
   knows that identity is a generator constant in `SETS`.)
2. **Stale "14 narrator components" counts** — `frontend/src/lib/openui/panelLibrary.ts:8` and
   the `tests/test_library_spec.py` module docstring (`(14 components …)`) predate the
   artifact-components build; the spec asserts 20.
3. **`library.ts` header is stale about the registry it introduces** — it says the set was
   "culled to ten" and lists the four infrastructure calls without their trailing `options`
   argument (`frontend/src/lib/openui/library.ts:1–14`). The code and spec are correct; the
   header is not.
4. **`Entrance` advertises options the schema does not define** — the schema comment and the
   `options` `describe()` say `{eyes, hair, glyph, art}`
   (`frontend/src/lib/openui/schemas/flavors.ts:151–164`), but `EntranceOptionsSchema` defines
   `markers`, and the taught signature and renderer use `markers`. The comment is D36-era drift;
   the gate is driven by the real keys, so nothing is mis-validated.
5. **`Interface` still implements retired modes** — `const MODES = ['terminal', 'phone', 'chat',
   'hologram', 'social']` (`components/Interface.svelte:28`) while the schema marks phone/chat/
   social deprecated (D59: use `Phone`/`SMS`/`SocialPost`) and the doc teaches only
   `terminal|hologram`. The schema types `mode` as a free string, so this is not a shape
   contradiction — but the renderer branches are a trap for a future author reading the
   component rather than the doc.
6. **`ScenePane`'s taught description mentions a retired panel** — "Holds the status panel and
   scene contents" (`library.ts:287` and the generator's `INFRASTRUCTURE` block) while
   `StatusPanel` is retired (AGENTS.md vocabulary). Model-facing copy only; no behavioural
   effect.

One expected, deliberate asymmetry for completeness: the renderer registry carries
`ArtifactCardDef` (the legacy alias) and the spec does not. That is the documented
alias-not-taught split (`REGISTRY_ALIASES` in `tests/test_library_spec.py`), not drift.
